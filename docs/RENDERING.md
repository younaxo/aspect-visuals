# Рендеринг интерфейса

Документ описывает, почему интерфейс раньше выглядел пиксельным и как устроен
пайплайн сейчас. Он нужен, чтобы правки не вернули старые проблемы.

## Откуда бралась пиксельность

Minecraft рисует GUI не в маленький буфер с последующим растягиванием: проекция
интерфейса ортографическая по логическому размеру экрана, а кадровый буфер
всегда полного разрешения. Значит виновата была не «низкая» отрисовка, а
**пространство координат, в котором строилась геометрия**.

1. **Формы.** Скругления растеризовались на CPU построчно через
   `DrawContext.fill(int, int, int, int, int)`. Аргументы целые и заданы
   в *логических* пикселях. При GUI Scale 3 один логический пиксель — это
   3x3 физических, поэтому каждая «ступенька» угла занимала 3 физических
   пикселя, а сглаживание по покрытию считалось с втрое меньшей частотой,
   чем есть на экране.
2. **Раннее округление.** Компоненты хранили координаты во `float`, но перед
   отрисовкой всё проходило через `Math.round`. Анимации двигались шагами
   в логический пиксель, то есть прыгали на 2-4 физических.
3. **Текстуры.** Текстуры ресурсов Minecraft по умолчанию создаются с
   `GL_NEAREST` и без mipmap: это правильно для блоков, но для иконок
   интерфейса даёт лесенку при увеличении и муар при уменьшении.
4. **Текст.** Штатный `ttf`-провайдер печёт глифы в растровый атлас
   фиксированного размера, а `DrawContext.drawText` ставит их по целым
   логическим координатам. При любом GUI Scale больше единицы глиф
   увеличивался как картинка.
5. **Обрезка.** `enableScissor` принимает целые логические координаты;
   округление дробных границ съедало пиксели сглаживания по краям.

## Как устроено сейчас

### Пространство физических пикселей

`UiScale` вычисляет плотность из окна: `framebufferWidth / scaledWidth`.
Раскладка по-прежнему считается в единицах макета (1 единица = 1 логический
пиксель Minecraft), но перед отрисовкой матрица масштабируется на `1 / scale`,
а координаты умножаются на `scale`. В результате **одна единица отрисовки
равна одному физическому пикселю**, дробные позиции доживают до растеризации,
а размер элементов на экране не меняется.

### Формы

Скруглённые прямоугольники, границы, тени и градиенты рисуются одним
core-шейдером `aspect_shape` через знаковое поле расстояния. Сглаживание
берётся из `fwidth` расстояния, то есть равно одному физическому пикселю
независимо от разрешения, GUI Scale и масштаба виджета. Граница считается
из той же фигуры, поэтому на углах нет стыков четырёх прямоугольников.

### Текст

Глифы Inter хранятся в MSDF-атласе и восстанавливаются в шейдере по медиане
трёх каналов. Текст остаётся резким на любом размере и позиционируется по
дробным координатам.

### Текстуры

UI-текстуры регистрируются отдельно от текстур мира: линейная фильтрация
и mipmap для уменьшения. Настройки Minecraft для pixel-art не наследуются.

## Что проверять при изменениях

- 1280x720, 1920x1080, 2560x1440 при GUI Scale 2, 3, 4 и Auto;
- углы карточек и переключателей при увеличении скриншота;
- края иконок и глифов;
- отсутствие рывков у анимаций вкладок и выпадающих списков.
